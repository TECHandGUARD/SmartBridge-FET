# Admin-managed staff accounts

Full administrators use **Admin → Staff Accounts** to add a registered account by email, assign duties, edit those duties, or disable staff access. Staff register and verify their own email using the existing account flow; the administrator verifies the person's identity before assignment. Adding staff does not send an email, set a password, change their primary role, or make them a full administrator. Existing full-administrator accounts cannot be converted through this panel.

The initial assignable duties are resource reviews, tutor assessment moderation, study-room moderation, announcements, and the university directory. Each has a working panel in `/staff`. All other administrator tools remain accessible to full administrators. Staff permissions are explicit duties, with the actions described beside each checkbox; this release does not split a duty into separate read/write/delete toggles.

Staff use their own login. Enabled staff are directed to the Staff workspace. The workspace checks permissions on entry, focus and every 30 seconds. Database checks use current account state on every request; a stale page cannot authorize an operation after suspension or permission removal. Existing signed resource URLs can last until their short expiry. Disabling staff access preserves the person's ordinary account and its original role.

Permissions are stored in an RLS-protected table, with direct browser writes revoked. Grant changes and the roster are available only through full-administrator RPCs. Optimistic versions reject concurrent stale edits. Full admin status is never inferred from editable authentication metadata or staff grants. The full-admin frontend check now recognizes both database-controlled full-admin representations (`is_super_admin` and `role=admin`), matching existing backend authorization.

Resource reviewers receive a bounded queue and can open referenced resource files. Their review operation can change moderation flags and server-owned review identity/time, but cannot edit ownership, prices, file URLs or learner documents. Assessment and study moderation reuse existing narrowly scoped review functions. Announcement and directory actions have explicit delegated RLS policies. The audit records the actual authenticated actor and operation; access-change records also include the chosen permissions and enabled state. Full admins see the latest 500 staff accounts and latest 100 audit entries.

Verification: the SQL fixture exercises full-admin grants, unknown permissions, stale edits, direct-write denial, self-escalation denial, unassigned modules, private-file boundaries, removed permissions, suspension, and audit creation. Browser fixtures cover phone and desktop creation/edit/suspension, scoped staff modules, access refresh and rejection of the full admin route. Browser services use isolated fixtures; live deployment verification does not create real staff grants or send invitations.
