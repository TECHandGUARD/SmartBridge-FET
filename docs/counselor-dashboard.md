# School counsellor dashboard

The public legal page is `/terms`. The previously shared `/TermsOfService` URL now redirects to that route. Both the legal page and application footer state that SmartBridge FET is operated by TECH AND GUARD (Pty) Ltd, registration 2026/155090/07. Trademark registration is not claimed.

The counsellor dashboard is `/counselor`. Administrators retain oversight; staff use the new database-controlled `school_counselor` role. Staff cannot self-assign that role or select their own learners. An administrator uses the dashboard assignment form with existing registered staff/learner emails and a school name, after verifying staff identity and institutional authority. The form explicitly changes the selected eligible account's primary role. Administrator and tutor accounts cannot be silently converted through this form.

A learner sees the school sharing request on their dashboard and must approve before staff can see that learner's name/email, university-application progress/deadlines or document checklist. Learners can revoke sharing. A school change returns the relationship to pending. Neither the legacy email-array roster nor a client-selected staff identity grants permission. Guardian-authority and school safeguarding procedures remain an operator responsibility; this workflow does not certify them.

A protected RPC returns only the authorised roster and minimal application/document metadata. It excludes account privilege fields, uploaded file paths and private notes. Records missing authoritative student ownership are excluded until an administrator reconciles them. Staff access to document binaries, document-verification write actions, the older chat and NBT-tracker components are outside this dashboard release and are not exposed here.

The dashboard supports roster search, application summaries, deadline flags, checklist categories, manual refresh, realtime permission/data signals and a 30-second refresh fallback. Checklist categories do not imply that every listed document is required by an institution. Pending/empty rosters have explicit guidance; query failures clear the previous roster rather than retaining private data.

Reminders derive their recipient and text in the database, require current approved learner access and deduplicate per staff/learner/South African calendar day. They create a durable notification and attempt email through the existing authenticated dispatcher. Provider acceptance is distinct from inbox delivery; missing sender configuration produces a queued message. Supabase Auth SMTP is still separate.
