# SmartBridge call relay

`handler.py` runs in `SmartBridgeCallRelay` (eu-west-1), Python 3.13 ARM64. Render `template.json` by replacing `Resources.Relay.Properties.Code.ZipFile` with the complete handler source before CloudFormation deployment. Validate the rendered template with CloudFormation ValidateTemplate. Reuse the existing stack parameters with UsePreviousValue when updating.

The template accepts an external Lambda execution role and diagnostic signaling channel. The role trusts lambda.amazonaws.com and permits Kinesis Video GetSignalingChannelEndpoint, GetIceServerConfig, DescribeSignalingChannel, CreateSignalingChannel and DeleteSignalingChannel only on `channel/smartbridge-relay-*/*` plus the diagnostic `channel/smartbridge-call-relay/*`. Create-with-tags also requires TagResource, restricted to the application channel prefix and Application tag. The exact execution policy is in `execution-role-policy.json`. ListSignalingChannels needs Resource `*`; log writes are restricted to `/aws/lambda/smartbridge-call-relay:*`. No stored AWS access keys are used.

The HTTPS function URL has public transport access; every browser request must carry a valid Supabase user token. The database checks open-room admission and a per-user request quota before returning the caller's trusted identity. TURN channels are scoped to room + user to avoid a single shared channel allocation limit. Credentials expire within five minutes. Existing allocations have a provider lifetime limit; the call requests fresh credentials and rotates ICE every 35 minutes. A scheduled hourly cleanup deletes channels older than 24 hours, up to 20 per run. TURN usage, signaling channels and AWS execution incur usage charges.

The frontend needs public `VITE_CALL_RELAY_URL` set to the stack RelayUrl output. Only the production AppOrigin receives browser CORS access. No server key belongs in Vite configuration. Relay passwords and JWTs must never be logged or stored in artifacts.

A main-branch-only GitHub OIDC role `SmartBridgeRelayTestRole` permits only invoking this Lambda. Its trust requires audience sts.amazonaws.com and subject repo:TECHandGUARD/SmartBridge-FET:ref:refs/heads/main. The encrypted-relay CI job obtains ephemeral credentials via the IAM-only diagnostic invocation (not accessible through Function URL bodies), forces TLS TURN in all peer connections, and checks real group and introductory classroom media and data delivery. The temporary credential file is deleted and never uploaded.

## Verification and limitations

Automated database tests cover fresh five-minute guest admission, host-only invites, idempotent notification creation, adult-account restrictions, six-person capacity, ended rooms and relay authorization/quota. Browser tests cover connected calls, mobile layouts, live maths slide edits, saving, privacy of speaker notes, live guests and actual relay media. Local browser builds without ICE support cannot substitute for the normal Chromium CI run.

Data saver is default, with lower outbound video/audio bitrates; audio-and-slides entry also disables incoming video. Network changes trigger ICE recovery. No carrier-specific assumptions are made. Physical iPhone/Android acceptance on MTN, Vodacom, Telkom, Cell C and school/local Wi-Fi remains required. Check call entry, speaker audio, switching Wi-Fi/mobile, audio-and-slides, edited slides and guest emails on each. School firewall policies, data bundles and signal strength can still prevent calls. AWS relay endpoints require IPv4 connectivity (including network-provided translation where applicable); pure IPv6-only deployments need separate acceptance. Mobile browsers that do not expose screen capture can still present PDF/native slides and view shared screens.

On 20 October 2026 the deployed Lambda successfully created new scoped room/user channels and returned two ICE server configurations with TLS relay endpoints and a 300-second credential lifetime. This verifies provider provisioning and IAM permissions; actual media traversal is checked separately by the main-branch encrypted-relay job. Normal browser regression checks use simulated cameras/microphones and isolated account/API fixtures.
